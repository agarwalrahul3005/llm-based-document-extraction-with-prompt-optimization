# LLM-Based Document Extraction with Prompt Optimization

This repository implements a document extraction pipeline for the FUNSD dataset using OCR, LLM-based extraction, and prompt optimization with GEPA.

## Project Overview

The project converts FUNSD annotations into a simplified ground-truth format, performs OCR with EasyOCR or Tesseract, extracts question-answer pairs with LLM-backed extraction, and evaluates both baseline and GEPA-optimized extraction.

## Repository Structure

- `data/`
  - `funsd/` - original FUNSD dataset splits and images
  - `ground_truth/` - converted ground truth JSON files
  - `ocr/easyocr/` - OCR outputs generated by EasyOCR
  - `ocr/tesseract/` - OCR outputs generated by Tesseract
- `experiments/`
  - `predictions/` - model extraction results
  - `gepa/` - GEPA-optimized program outputs
  - `results/` - evaluation JSON results
  - `figures/` - aggregated result tables and plots
- `src/` - source code modules and command-line scripts

## Prerequisites

This project depends on Python and several libraries, including:

- `dspy`
- `easyocr`
- `pytesseract`
- `opencv-python`
- `pandas`
- `matplotlib`
- `argparse`

It also expects an Ollama-compatible model server at `http://localhost:11434` for `dspy`-based extraction.

### Ollama setup

If you use the `dspy` extraction and GEPA scripts, install Ollama and pull the required models locally. For example:

```bash
# install Ollama if not already installed
# see https://ollama.com/docs for platform-specific instructions

ollama pull llama3
ollama pull qwen2.5:7b
ollama pull gemma3:4b
ollama pull mistral
```

Then start the Ollama server before running the extraction or optimization scripts:

```bash
ollama serve
```

## Usage

From the repository root:

```bash
cd src
```

### 1. Convert FUNSD annotations to ground truth

```bash
python -m convert_funsd_to_gt --dataset testing
```

Available dataset values: `train`, `validation`, `testing`

### 2. Run OCR

EasyOCR:

```bash
python -m ocr.easyocr --dataset testing
```

Tesseract:

```bash
python -m ocr.tesseract --dataset testing
```

OCR output is written into `data/ocr/easyocr/<dataset>/` or `data/ocr/tesseract/<dataset>/`.

### 3. Run baseline DSPy extraction

```bash
python -m extractors.baseline_dspy --model qwen25
```

This reads OCR outputs from `data/ocr/easyocr/testing/` by default and writes predictions to `experiments/predictions/qwen25/`.

### 4. Evaluate baseline extraction

```bash
python -m evaluation.evaluate_dspy --model qwen25
```

This compares predictions against `data/ground_truth/testing/` and writes results to `experiments/results/qwen25.json`.

### 5. Train GEPA prompt optimization

```bash
python -m optimization.train_gepa --model qwen25
```

This uses the training and validation datasets and saves an optimized program to `experiments/gepa/qwen25/`.

### 6. Run GEPA-optimized extraction

```bash
python -m extractors.run_gepa --model qwen25
```

This uses the optimized program and writes predictions to `experiments/predictions/qwen25_gepa/`.

### 7. Evaluate GEPA extraction

```bash
python -m evaluation.evaluate_gepa --model qwen25
```

This compares GEPA predictions against `data/ground_truth/testing/` and writes results to `experiments/results/qwen25_gepa.json`.

### 8. Compare model results and generate plots

```bash
python -m evaluation.compare_models
```

This aggregates all result files in `experiments/results/` and writes summary CSV and figures to `experiments/figures/`.

## Notes

- `baseline_dspy.py` and `run_gepa.py` currently assume EasyOCR output under `data/ocr/easyocr/testing/`.
- `train_gepa.py` uses the `dspy.GEPA` optimizer and requires valid `dspy` and local Ollama model access.
- If you need to change the dataset split, pass `--dataset` to the conversion, OCR, and evaluation scripts.

## Example Workflow

```bash
cd src
python -m convert_funsd_to_gt --dataset testing
python -m ocr.easyocr --dataset testing
python -m extractors.baseline_dspy --model qwen25

python -m extractors.run_gepa --model qwen25
python -m evaluation.evaluate_gepa --model qwen25
python -m evaluation.compare_models
```
